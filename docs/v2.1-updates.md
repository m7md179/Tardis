# TARDIS v2.1 Updates

Summary of all changes since v2.0.0.

---

## New: Skill Engine Plugin

A self-evolving skill tracking system. Track skills, run adaptive training sessions calibrated to 85% success, detect weak areas, earn XP, and auto-create Todoist tasks when you fall behind.

Full documentation: [skill-engine.md](./skill-engine.md)

**Highlights:**
- Add tech and non-tech skills to track
- Training sessions with adaptive difficulty (1-10)
- XP system with leveling (diminishing returns formula)
- Weak area detection from low-score patterns
- Streak tracking across consecutive training days
- Todoist auto-task creation for weak areas and stale skills
- Full Gemini integration — say "I want to learn TypeScript" and it just works

**Commands:** `add-skill`, `remove-skill`, `skills`, `train`, `complete-training`, `progress`, `weak-areas`, `stats`, `calibrate`, `config`

## New: Shared Database Package (`@tardis/db`)

A new shared package providing SQLite database access to all of TARDIS via Drizzle ORM + bun:sqlite.

- Database file: `/var/lib/tardis/tardis.db`
- WAL mode enabled for concurrent reads
- Foreign keys enforced
- Auto-migration on first connection (CREATE TABLE IF NOT EXISTS)
- Configurable via `TARDIS_DATA_DIR` or `TARDIS_DB_PATH` environment variables

Plugins can now access the database through the PluginAPI:

```typescript
const db = api.db.drizzle(); // raw Drizzle instance
api.db.run(sql, params);     // INSERT/UPDATE/DELETE
api.db.query(sql, params);   // SELECT
```

New permissions: `db:read`, `db:write` — plugins must declare these in their manifest to access the database.

## Todoist Token from Telegram

**Problem:** The Todoist API token had to be pre-configured in `config.json` before server start. No way to set or update it at runtime from Telegram.

**Fix:** New `config` command in Telegram:

```
config todoist <token>     # Set and persist the Todoist API token
config todoist             # Check if token is set
```

The token is immediately applied to the running client and persisted to `config.json` so it survives server restarts.

**Bonus fix:** There were two separate `TodoistClient` instances — one used by plugins/Gemini and one created inside the Telegram command handler. Updating the token on one wouldn't affect the other. Now a single shared `TodoistClient` is passed through the entire system.

## Smarter Gemini Assistant

Major improvements to the AI assistant's intelligence and capabilities:

### Agentic Behavior
- **Bias toward action** — acts immediately when it has enough information instead of asking for confirmation
- **Multi-step chaining** — chains up to 8 function calls per message automatically
- **Error recovery** — retries with alternatives before giving up (checks `available_tasks`, tries different matches)

### Examples of Multi-Step Chains

| You say | Functions called |
|---------|----------------|
| "start working on standup" | `get_status` → `stop_tracking` (if active) → `start_tracking` |
| "add today's standup and start it" | `add_task` → `start_tracking` |
| "I'm done with X, mark it complete" | `stop_tracking` → `complete_task` |
| "I want to learn Python" | `run_plugin_command` (skill-engine add-skill) |

### Inter-Plugin Communication
- New `run_plugin_command` function lets Gemini invoke any loaded plugin's commands
- Returns captured output text so Gemini can relay results naturally
- System prompt includes list of all available plugins and their commands

### Richer Context
- Current time and day of week (Riyadh timezone) included in every request
- Up to 15 Todoist tasks shown (up from 10) with priority info
- Available plugins and their commands listed
- 12 conversation history entries (up from 10) for better multi-turn context

## Plugin Help Command

Every plugin now has a built-in `help` command that displays its commands, arguments, hooks, and config keys — no implementation needed.

**CLI:**
```bash
tardis plugin run skill-engine help
tardis plugin run pomodoro-timer help
```

**Telegram:**
```
plugin skill-engine help
plugin gemini-assistant help
```

Output shows:
- Plugin name, version, description
- All commands with their arguments and descriptions
- Registered hooks
- Available config keys

### Plugin Manifest: `args` Field

Plugin commands now support an `args` field in the manifest to describe usage:

```json
{
  "commands": [
    {
      "name": "train",
      "args": "<skill> [type]",
      "description": "Start a training session"
    }
  ]
}
```

This is displayed in `help` output and `plugin list`.

Bot commands are now registered with Telegram's menu system. Typing `/` in the chat shows all available commands with descriptions:

- `/stop` — Stop current task

- `/status` — Show what you're tracking

- `/tasks` — Show Todoist tasks
- `/add` — Create a Todoist task
- `/config` — Set configuration
- `/plugin` — Run a plugin command
- `/help` — Show all commands

## 12hr Time Format Fix

**Problem:** Gemini would send time windows in 12hr format (e.g. "2:30pm-3pm") but TARDIS only read 24hr format `[HH:MM-HH:MM]`.

**Fix (three layers):**

1. **Gemini function descriptions** now explicitly say "ALWAYS use HH:MM-HH:MM format" for `time_window` parameters
2. **`normalizeTimeWindow()` helper** in the Gemini plugin converts any 12hr input to 24hr `[HH:MM-HH:MM]` before passing to Todoist
3. **`parseTimeWindow()` in shared utils** now supports 12hr format with optional minutes as a fallback safety net
